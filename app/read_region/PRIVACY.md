The tool reads only native signed Dify upload previews at the API origin obtained from one authenticated native upload-grant metadata RPC (no actual upload or file creation). It accepts no external URL, local path, API key, model configuration or image registry ID. Signed URLs are bearer capabilities validated by the Dify server; the plugin does not claim a new cross-invocation authorization system. Raw filenames and signed URLs are not returned or logged by this code.

Original image pixels or an unscaled crop are returned as a PNG BLOB and small geometry JSON. Native Dify may store the derived file, and New Agent read_media sends actual image content to the selected vision-model provider. Dify/provider retention and access policies continue to apply; the plugin makes no OCR or direct model-provider call; native file metadata RPC and bounded preview GET are the only fetch path. No application JSON, private service or custom Agent strategy is required. Native-origin RPC metadata absent or unsupported file routes fail closed.

Supported proof target is Dify1.20.0 New Agent with its native read_media vision path. Classic/1.18 image outputs do not establish subsequent model vision context. Other deployments and real-model quality require verification; no silent upgrade or universal data-security guarantee is implied.
